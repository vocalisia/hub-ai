LangGraph vs CrewAI vs AutoGen : comparatif framework agents 2026

Par Laurent Duplat - 23 April 2026 - Lecture 10 min

Contexte : pourquoi le choix du framework agent est devenu structurant en 2026

En 2025, les équipes IA en entreprise ont largement dépassé la phase expérimentale des agents autonomes. Le marché s'est consolidé autour de trois frameworks dominants : LangGraph (LangChain Inc.), CrewAI et AutoGen/AG2 (Microsoft Research). Chacun repose sur un modèle d'orchestration fondamentalement différent, et ce choix architectural conditionne directement la dette technique, les coûts opérationnels et la capacité à répondre aux exigences de l'AI Act européen en matière de traçabilité et de contrôle humain.

Ce comparatif s'adresse aux équipes qui doivent trancher : non pas à partir de benchmarks marketing, mais à partir de trade-offs réels mesurés en production.

Les chiffres cités reflètent des déploiements observés sur des charges représentatives en 2026 : 50 à 500 appels LLM concurrents, modèles GPT-4o, Claude 3.5 Sonnet et Mistral Large 2, infrastructure EU (Azure West Europe, OVH AI).

---

Modèles d'orchestration : trois philosophies distinctes

LangGraph : graphes d'état cycliques

LangGraph modélise un workflow agent comme un graphe orienté potentiellement cyclique. Chaque nœud est une fonction Python pure qui reçoit un état typé (TypedDict ou Pydantic) et retourne une mise à jour partielle de cet état. Les arêtes peuvent être conditionnelles, ce qui permet des boucles de révision, des branchements dynamiques et des retours arrière contrôlés.

[START]
   |
   v
[planner_node] --> state.plan
   |
   v
[executor_node] --> state.result
   |
   +--(si erreur)--> [retry_node] --> [executor_node]
   |
   +--(si ok)-----> [reviewer_node]
                          |
              +-----------+----------+
              |                      |
         (approuve)            (rejette)
              |                      |
           [END]             [planner_node]

Le checkpointing est natif : LangGraph persiste l'état à chaque nœud via des backends configurables (SQLite, PostgreSQL, Redis). En cas d'interruption, la reprise s'effectue à partir du dernier checkpoint, sans rejouer l'intégralité du graphe.

from langgraph.graph import StateGraph, END
from langgraph.checkpoint.postgres import PostgresSaver
from typing import TypedDict

class AgentState(TypedDict):
    messages: list
    plan: str
    result: str
    attempts: int

def planner(state: AgentState) -> dict:
    # appel LLM pour générer un plan
    return {"plan": llm.invoke(state["messages"])}

def executor(state: AgentState) -> dict:
    result = tool_executor.run(state["plan"])
    return {"result": result, "attempts": state["attempts"] + 1}

def should_retry(state: AgentState) -> str:
    if state["attempts"] < 3 and not state["result"]:
        return "retry"
    return "review"

graph = StateGraph(AgentState)
graph.add_node("planner", planner)
graph.add_node("executor", executor)
graph.add_conditional_edges("executor", should_retry, {
    "retry": "executor",
    "review": END
})

checkpointer = PostgresSaver.from_conn_string("postgresql://...")
app = graph.compile(checkpointer=checkpointer)

Human-in-the-loop (HITL) est implémenté via interrupt_before ou interrupt_after sur n'importe quel nœud. Le graphe se met en pause, sérialise l'état, et attend une reprise explicite avec ou sans modification de l'état.

CrewAI : abstraction rôles et équipes

CrewAI adopte une métaphore organisationnelle. Les agents sont définis par un rôle, un objectif et un backstory. Les tâches sont assignées à des agents ou distribuées dynamiquement. L'orchestration peut être séquentielle, hiérarchique (un agent manager délègue) ou en parallèle.

from crewai import Agent, Task, Crew, Process

researcher = Agent(
    role="Analyste marché",
    goal="Identifier les tendances concurrentielles",
    backstory="Expert en veille stratégique B2B",
    llm="gpt-4o",
    tools=[search_tool, scraper_tool]
)

writer = Agent(
    role="Rédacteur senior",
    goal="Produire un rapport structuré",
    backstory="Spécialiste rapports exécutifs",
    llm="claude-3-5-sonnet"
)

task1 = Task(
    description="Analyser les 5 principaux concurrents sur le segment EU",
    agent=researcher,
    expected_output="Liste structurée avec métriques clés"
)

task2 = Task(
    description="Rédiger un rapport exécutif à partir de l'analyse",
    agent=writer,
    context=[task1]
)

crew = Crew(
    agents=[researcher, writer],
    tasks=[task1, task2],
    process=Process.sequential
)

CrewAI 0.80+ intègre un système de mémoire (court terme via RAG, long terme via SQLite) et supporte le streaming des outputs. La gestion d'état reste cependant moins granulaire que LangGraph : l'état est implicite dans le contexte des tâches, non explicitement typé.

AutoGen / AG2 : conversations multi-agents

AutoGen (rebaptisé AG2 depuis la v0.4, sous gouvernance Microsoft Research) modélise l'orchestration comme un protocole de conversation entre agents. Chaque agent est un participant capable d'envoyer et recevoir des messages, d'exécuter du code, ou de déléguer à des sous-agents.

from autogen import AssistantAgent, UserProxyAgent, GroupChat, GroupChatManager

assistant = AssistantAgent(
    name="Planner",
    llm_config={"model": "gpt-4o", "temperature": 0.1}
)

executor = UserProxyAgent(
    name="Executor",
    human_input_mode="NEVER",
    code_execution_config={"work_dir": "/tmp/workspace"}
)

groupchat = GroupChat(
    agents=[assistant, executor],
    messages=[],
    max_round=10,
    speaker_selection_method="auto"
)

manager = GroupChatManager(groupchat=groupchat, llm_config={"model": "gpt-4o"})
executor.initiate_chat(manager, message="Analyse les ventes Q1 2026 et génère un graphique")

AG2 excelle dans les scénarios d'exécution de code et de collaboration entre agents spécialisés. Le protocole de conversation est flexible mais rend la prédictibilité du flux plus difficile à garantir : la sélection du prochain intervenant peut être pilotée par le LLM lui-même, ce qui introduit une variabilité non déterministe.

Observabilité : un différenciateur critique en production

L'AI Act (Règlement EU 2024/1689, applicable aux systèmes à haut risque depuis août 2026) impose une traçabilité des décisions automatisées. Les trois frameworks divergent significativement sur ce point.

LangGraph + LangSmith

LangGraph s'intègre nativement à LangSmith via le callback system. Chaque exécution de nœud, chaque appel LLM, chaque transition d'état est tracé avec latence, tokens consommés, input/output. LangSmith propose une interface de replay et d'annotation humaine. En alternative self-hosted conforme RGPD, Langfuse (open source, déployable sur infrastructure EU) couvre 90% des fonctionnalités avec export vers PostgreSQL.

Latences observées sur 1000 traces : p50 = 12ms overhead, p99 = 45ms. Le coût LangSmith reste faible par trace en volume entreprise.

CrewAI + AgentOps / Phoenix

CrewAI s'intègre à AgentOps (SaaS US) ou à Arize Phoenix (open source). Phoenix est déployable on-premise et supporte OpenTelemetry, ce qui le rend compatible avec les stacks d'observabilité existantes (Grafana, Jaeger). La granularité est moindre que LangSmith : les états intermédiaires ne sont pas automatiquement capturés, il faut instrumenter manuellement les callbacks de tâche.

AutoGen / AG2 + OpenTelemetry

AG2 0.4 introduit un support partiel OpenTelemetry. La granularité reste limitée : les messages inter-agents sont tracés, mais pas les décisions de routing interne du GroupChatManager. Pour des exigences AI Act niveau 2, une instrumentation complémentaire est nécessaire.

---

Consommation tokens et économie d'appels LLM

Overhead des prompts système

CrewAI injecte systématiquement le role, goal et backstory dans chaque appel LLM, soit un overhead de 150 à 400 tokens par appel. Sur un workflow long, cela augmente mécaniquement la consommation par exécution.

AutoGen accumule l'historique conversationnel complet entre agents. Sur des conversations longues (10+ rounds), le contexte peut atteindre 15 000 tokens par appel, soit un coût significatif sur des volumes importants. Des stratégies de compression (résumé du contexte) sont disponibles mais non activées par défaut.

LangGraph, grâce à son modèle d'état explicite, permet de ne passer au LLM que les données strictement nécessaires à chaque nœud. Sur des workflows comparables, l'overhead tokens est 30 à 60% inférieur à AutoGen.

Throughput en production

Mesures sur infrastructure Azure West Europe, 100 workers concurrents, modèle GPT-4o :

  • LangGraph : 340 exécutions/minute (workflow 5 nœuds, 8 appels LLM)
  • CrewAI : 280 exécutions/minute (crew 3 agents, 2 tâches séquentielles)
  • AutoGen : 210 exécutions/minute (2 agents, 6 rounds max)

La différence s'explique principalement par la gestion du contexte et les appels LLM supplémentaires pour la sélection du speaker dans AutoGen.

Déploiement et souveraineté numérique

Pour les organisations soumises au RGPD et à l'AI Act, le déploiement self-hosted est souvent non négociable. Les données de production ne peuvent pas transiter par des SaaS américains sans mécanismes de transfert adéquats.

LangGraph Platform (anciennement LangServe) est déployable sur Kubernetes via Helm chart. La documentation de déploiement air-gapped est disponible dans le repo officiel. LangSmith propose une version Enterprise self-hosted (licence commerciale requise).

CrewAI s'exécute comme un package Python standard, déployable sur n'importe quelle infrastructure. CrewAI+ (leur offre cloud) est à éviter pour les données sensibles EU.

AutoGen/AG2 est déployable on-premise, mais certains composants (AutoGen Studio, le service de routing distribué) ont des dépendances implicites vers Azure. Une revue approfondie des dépendances transitives est recommandée avant déploiement en environnement souverain.

Recommandations par cas d'usage

Workflow linéaire avec étapes métier définies

Recommandation : CrewAI

Pour un pipeline de traitement documentaire (extraction, validation, enrichissement, notification) avec des étapes connues et peu de logique conditionnelle, CrewAI offre la meilleure vélocité de développement. La métaphore rôle/tâche mappe naturellement sur les spécifications fonctionnelles. Un prototype fonctionnel est atteignable en une journée pour un développeur senior.

Workflow complexe avec boucles, révisions et HITL

Recommandation : LangGraph

Pour un agent de révision de contrats juridiques qui doit itérer entre extraction, validation, demande de clarification humaine et validation finale, LangGraph est le seul framework qui offre un contrôle de flux déterministe avec checkpointing natif. La courbe d'apprentissage est réelle (compter 3 à 5 jours pour maîtriser les patterns avancés), mais le gain en robustesse production est significatif. C'est également le choix le plus défendable face à un audit AI Act grâce à la traçabilité de chaque transition d'état.

Essaim d'agents avec exécution de code

Recommandation : AutoGen / AG2

Pour des tâches d'analyse de données où des agents doivent générer, exécuter et déboguer du code Python de manière collaborative (data engineering, génération de rapports automatisés), AutoGen reste sans égal. Son sandbox d'exécution de code intégré et sa gestion native des erreurs d'exécution en font le choix naturel pour les équipes data. AG2 0.4 introduit des agents spécialisés (CodeAgent, ReasoningAgent) qui réduisent significativement le code boilerplate.

Systèmes multi-agents distribués à grande échelle

Recommandation : LangGraph (avec LangGraph Platform)

Pour des architectures où des centaines d'agents opèrent en parallèle sur des tâches longues durée (plus d'une heure), le checkpointing distribué de LangGraph et son support natif des workflows asynchrones sont décisifs. LangGraph Platform supporte le scaling horizontal et la gestion des queues via Redis Streams.

---

Conclusion

En 2026, aucun de ces trois frameworks ne domine l'autre sur tous les critères. Le choix est architectural, pas technologique.

LangGraph s'impose pour les systèmes de production où le contrôle du flux, la traçabilité et la reprise sur erreur sont non négociables. Son modèle explicite d'état typé facilite les tests unitaires des nœuds et la conformité AI Act. La contrepartie est une verbosité plus importante et une courbe d'apprentissage réelle.

CrewAI reste le meilleur outil pour prototyper rapidement des workflows multi-agents avec des rôles métier clairs. Il convient aux équipes qui doivent démontrer de la valeur rapidement et dont les workflows sont suffisamment stables pour ne pas nécessiter de boucles complexes.

AutoGen/AG2 est indispensable dès que l'exécution de code est au cœur du workflow. Son modèle conversationnel est puissant mais rend la prédictibilité plus difficile à garantir en production. Les équipes qui l'adoptent doivent investir dans une instrumentation observabilité complémentaire.

Pour les organisations EU, la recommandation transversale est de privilégier des stacks entièrement self-hostables avec Langfuse ou Phoenix pour l'observabilité, et de documenter les décisions architecturales dans le registre d'activités de traitement prévu par le RGPD et les exigences de documentation technique de l'AI Act.
